# 工业维保 UI 设计原则

状态：v1.1 治理修订候选。替代旧版将高密度信息与高密度表格作为普遍默认值的表述；旧版保留于 Git 历史。不是产品 UI 实测结论。

## 核心目标

- 工业维保、专业克制、数据可信、证据留痕、现场友好。
- 以任务完成、异常识别、操作可理解性与可访问性优先，不把信息密度或视觉风格当作独立目标。
- 保留产品品牌、必要业务功能与安全边界。

## 分层与密度

- 商业操作层：简洁明快，优先核心状态、异常、趋势及常用操作；减少重复卡片、非必要一级菜单和工程参数。
- 专业维护层：按需展开诊断、原始证据和完整日志，保留查询与导出；不得因视觉简化隐藏关键告警或风险确认。
- 数据表：按照任务、屏幕、文本长度及现场环境选择密度。必要时提供紧凑模式，而非强制高密度。
- 等宽或等宽数字仅用于地址、代码、测量数字及需要对齐的字段；中文正文优先清晰易读的字形。

## 视觉与交互

- 主色克制，状态色语义明确；圆角、阴影和动效服务于层级，而非机械禁止某种风格。
- 空状态、错误状态、加载状态必须有业务解释；未知、未测、失败、离线与成功不得混用。
- 状态不能仅用颜色表示，应配合文字、图标或其他可辨识线索。
- 以 WCAG 2.2 AA 为 Web 可访问性设计目标：普通文字对比度至少 4.5:1，大字号文字至少 3:1（适用例外按标准）；键盘操作、可见焦点、必要非文本对比度纳入评审。桌面客户端按适用性参考，不宣称认证或合规。
- 在目标操作系统、缩放比例、分辨率和实际交互场景分别验证；未经测试不作通过结论。
